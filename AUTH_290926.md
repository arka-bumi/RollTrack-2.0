## 1. Masalah yang diselesaikan

### 1.1 PIN disimpan dan dibandingkan sebagai plaintext

`rolltrack-backend/src/models/User.ts`
```ts
pin: { type: String, required: true },
```
`rolltrack-backend/src/routes/api.ts:19`
```ts
const user = await User.findOne({ name });
```
Dampak: dump MongoDB langsung membocorkan PIN seluruh operator.

### 1.2 PIN tidak pernah diverifikasi di sisi mobile

`rolltrack-mobile/src/data/store.tsx`
```ts
if (found && pin.length === 6) {   // hanya menghitung panjang
```
Backend tidak pernah dipanggil. 6 digit apa pun masuk sebagai operator mana pun.

### 1.3 Tidak ada token, semua endpoint terbuka

Response login hanya objek user — tanpa JWT. `PUT /sheets-connection` dan `POST /sync/full` terbuka untuk siapa pun.

### 1.4 `tim_cutting` berasal dari body request

Klien bisa menulis nama siapa pun. Setelah JWT ada, `tim_cutting` diturunkan dari token.

### 1.5 Kunci enkripsi punya fallback hardcoded

```ts
const SECRET_KEY = process.env.ENCRYPTION_KEY || 'malilkids_rolltrack_secret_key_32b!';
```

## 5. Model User (final)

```ts
name:       string, required, unique   // nama lengkap; tampil di dropdown Pilih Operator, dipakai login
pin_hash:   string, required, select: false
role:       'operator' | 'admin' | 'superadmin'
team?:      string
must_change_pin: boolean, default false
```
Tanpa `username` (login pilih nama, bukan ketik — jawaban user) dan tanpa `brand` (D1).
Nama ditolak bila sudah dipakai user lain.

## 6. Langkah implementasi (belum dikerjakan — tunggu perintah build)

Urutan wajib: L1 sebelum L2.

- **L1** — Verifikasi PIN di backend: `bcryptjs` + `jsonwebtoken` + `express-rate-limit`; `User.pin` → `pin_hash`; `authService.ts` + `routes/auth.ts` baru; pesan error identik (anti-enumeration).
- **L2** — Token & kunci: `tokenService.ts` + `middleware/auth.ts`; `requireAuth` global; `/auth/login` + `/health` publik; hapus fallback `ENCRYPTION_KEY`.
- **L3** — Guard: `POST /sync/*` → admin+; `GET /sheets-connection` → admin+; `PUT /sheets-connection` → superadmin; user endpoints → §4.
- **L4** — `tim_cutting` dari token (hapus dari DTO cut + transfer); validasi enum `brand` semua boundary.
- **L4b** — `shared/domain/brandRouting.ts`: `groupByBrand`; `syncFull` pakai ini; test split 3:2.
- **L5** — Rate limit login: 5/15 menit per IP, 429 pesan jelas.
- **L6** — Mobile API sungguhan: `lib/api.ts` + token `AsyncStorage`; `login(name, pin)` dengan `name` dari dropdown Pilih Operator (PRD §3.1), bukan ketikan bebas; hapus `SEED_USERS` dari login; pesan offline di LoginScreen.
- **L7** — Seed Super Admin: `scripts/seed-superadmin.ts`, idempoten, PIN default `000000`, set `must_change_pin`.
- **L8** — Endpoint user: `POST/GET /users`, `PUT /users/:id`, `DELETE /users/:id`, `PUT /auth/change-pin`; admin hanya boleh buat operator (V14). Hapus user = hapus data login saja; seluruh log/history atas nama user **tetap tersimpan** (jawaban user). Nama baru ditolak bila sudah dipakai.
- **L9** — UI bertahap: list → tambah → edit → hapus (konfirmasi; hanya login yang terhapus); QR download encode Roll ID, Admin/Super Admin saja.
