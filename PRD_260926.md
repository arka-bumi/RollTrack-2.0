# Product Requirements Document (PRD) — RollTrack
*Manajemen Pelacakan Gulungan Kain Gudang — kebutuhan produk saja (tanpa tech flow)*

## 0. Glosarium
| Istilah | Arti |

## 1. Tujuan & Latar Belakang
**RollTrack** adalah aplikasi mobile operasional gudang kain milik satu perusahaan dengan **dua merek terpisah: Malilkids dan Anakkecilku**. Masing-masing merek memiliki **master data dan persediaan sendiri** yang tidak boleh bercampur.

Setiap roll kain dilacak per gulungan fisik (*Unique Physical Roll Tracking*) dan diidentifikasi unik via QR Code berisi **Roll ID** (identitas roll + ukuran fisiknya), karena panjang/berat tiap roll di lapangan selalu bervariasi.

- **Target pengguna:** 10–15 orang (Staff Gudang, Admin, Super Admin).
- **Batasan finansial:** seluruh informasi harga / nilai uang **tidak ditampilkan** di aplikasi; fokus murni operasional fisik stok kain.
- **Peran aplikasi:** alat **input** untuk spreadsheet **Inventory Kain (MALILKIDS)** dan **Inventory Kain (ANAKKECILKU)** — setiap inputan masuk ke spreadsheet merek yang sesuai pengaturan.

## 3. Persyaratan Fungsional

### 3.1. Login (PIN Operator)
- **Dropdown "Pilih Operator"** + PIN 6 digit via numpad (bukan mengetik username bebas).
- **Login selalu membutuhkan koneksi** — PIN diverifikasi server. Setelah berhasil, sesi bertahan sehingga staff bisa lanjut bekerja walau kemudian offline.
- Setiap akun terikat pada satu peran (staff / admin / super_admin) yang menentukan hak akses di §2.
- **Akun super admin pertama** dibuat dari PIN default (nilai tetap di ARCH §6); Super Admin menggantinya sendiri lewat **Akses dan Sinkronisasi**, di atas daftar Admin.
- **Super Admin** = pemilik sistem: mendaftarkan admin baru, mengatur koneksi spreadsheet, dan mengakses semua fitur.

### 3.2. Master Data Read-Only (empat sumber acuan)
1. **F. Database Kain** — dipakai hanya untuk **lookup SKU Kain → Jenis Kain** (label/enrichment tampilan). Tidak tampil sebagai daftar di aplikasi.
2. **F. Database Produk** — dipakai hanya sebagai **pilihan dropdown saat potong kain**: Jenis, Produk, Varian (size), SKU Produk, status aktif, dan relasi SKU Kain per Kain Ke-.
   - **Tidak pernah ditampilkan** sebagai daftar di aplikasi.
   - Dropdown hanya memuat produk berstatus **Aktif**, terfilter per merek, dan terdedup per SKU Produk (satu produk multi-kain tampil satu entri; tanpa rincian kain — setelah dipilih hanya Nama Produk dan Varian yang ditampilkan). Cari/pilih by SKU atau nama; setelah pilih, Nama Produk dan Varian muncul otomatis. Label tiap entri berformat `{SKU Produk} - {Produk} - {Varian}` (mis. `GDSSDGRM - Geos Premium - Grey Polka - M`); pencarian mencocokkan substring ke SKU maupun Nama (case-insensitive); urutan entri dikunci: Nama Produk A→Z, lalu Varian S→M→L→XL, lalu SKU Produk sebagai tiebreak. (Teks dropdown di mockup 3.1 tidak menampakkan Varian — mockup tidak diperbarui, format di sini yang berlaku; lihat DESIGN §4.12.)
   - `relasi_kain` (Jenis Motif x SKU Kain, konversi) **tidak dipakai untuk menampilkan data roll** — data roll (jenis/motif/SKU/sisa) selalu berasal dari Database Kain merek aktif, bukan dari relasi produk. Relasi hanya untuk konversi/lookup.
   - Nilai konversi Meter↔Pcs di master ini **tidak dihitung/dipakai aplikasi** — kalkulasi itu milik spreadsheet (§3.3).
3. **History Kain Datang** — dipakai saat **scan / tulis Roll ID** untuk cek VALID dan menampilkan profil roll.
4. **Master Gudang** — sumber daftar nama gudang untuk Pindah Gudang (2.4) dan filter lokasi di Kain (4.3/4.4). Isinya **identik di kedua file spreadsheet**, itu sebabnya layar Pindah tidak memakai toggle merek.
- Semuanya read-only dari HP: tidak ada pendaftaran roll baru, tidak ada ubah master dari aplikasi. Masing-masing merek punya isi master sendiri, kecuali Master Gudang.

### 3.3. Pemotongan Kain (Cutting) — multi-merek
- **Langkah pertama wajib: pilih merek (Malilkids / Anakkecilku)** lewat toggle di 3.1 dan 3.5. Seluruh rujukan berikutnya (master kain, master produk, daftar roll, kode produksi) mengikuti merek terpilih. Merek dipilih di **Cutting** dan di **Kain (4.1–4.5)**; tidak dipilih di Pindah Gudang (§3.4).
- Alur: pilih **merek** → toggle produksi/non-produksi → tanggal potong + NN → cari/pilih produk by SKU/nama (auto Nama Produk + Varian) → Kode Produksi terbentuk → **kunci via ikon gembok** pada kotak preview (selama terkunci, dropdown produk/tanggal/NN tak bisa berubah — mencegah klik tak sengaja mengganti kode; buka gembok = bisa ubah lagi tanpa reset batch) → klik "Tambah Roll Kain" → scan QR **atau** tulis Roll ID manual (cek VALID + kartu hasil: Roll ID, Jenis•Motif•SKU, Sisa Meter Terkini saja — tanpa Sisa Kg, tanpa lokasi gudang; bebas pakai kain manapun selama milik merek aktif) → input Panjang Potong (m) / Estimasi Berat (Kg) + radio Sisa/Habis + preview hitung live + waste/reject opsional → klik Potong Kain (jadi baris pertama) → ulangi "Tambah Roll Kain" untuk roll ke-2 dst → **Simpan Transaksi** = N baris di History Penggunaan Kain dengan Kode Produksi yang sama. Setelah Simpan berhasil (dari 3.1 maupun 3.5), aplikasi kembali ke 3.1 Potong Kain fresh (reset batch: kunci kode dibuka, daftar roll dikosongkan, pilihan produk/NN direset, tanggal default hari ini) dengan toast sukses agar staff langsung lanjut cutting berikutnya; bila gagal (duplikat/beda merek/Habis) tetap di layar + pesan jelas.
- **Meter diutamakan.** Staff lebih sering isi Jumlah Dibawa (Meter); kolom Estimasi Berat (Kg) diisi manual bila perlu. Bila keduanya diisi, kalkulasi memakai meter. Bila **hanya Kg**, konversi ke meter memakai kolom `(Meter/Kg) atau (Meter/Yard)` (`rasio_konversi_meter`) di F. Database Kain. Sisa berjalan selalu dalam meter; aplikasi **tidak menghitung dan tidak menampilkan sisa Kg** (kolom sisa Kg tidak ada di spreadsheet — keputusan ringan proses).
- Kolom `Tim Cutting` diisi **nama orang** yang memotong (dari sesi login), bukan nama tim.
- **Mode non-produksi (3.5):** staff hanya mengisi **Nama Produk** bebas. Layar 3.5 tidak memiliki field NN/No. Batch. Ditulis ke History Penggunaan Kain: Tanggal ke kolom A (Tanggal), Nama Produk bebas (mis. sample) ke kolom G (Produk); kolom F (Kode Produksi), H (SKU Produk), I (Keyword Konversi Pcs) dikosongkan — sehingga aturan dedup Kode Produksi tidak berlaku untuk transaksi non-produksi. Sisanya (roll, meter/kg, waste/reject, status, tim) sama seperti produksi.
- **Kode Produksi** format `{M|A}{DDMMYY}-{SKU_PRODUK}-{NN}`, dengan `M` = Malilkids, `A` = Anakkecilku. **NN (nomor urut) diinput manual oleh staff** — bukan dibikin otomatis; kombinasi (merek, tanggal, SKU, NN) yang sama ditolak.
- Mendukung input **waste & reject** per transaksi dan mode **potong non-produksi** (sample).
- **Waste & Reject tidak mengurangi kain.** Keduanya murni angka untuk tim inventory menghitung tingkat waste/reject per roll di spreadsheet; tidak masuk perhitungan aplikasi dan **tidak mengurangi sisa roll**. Sisa roll hanya berkurang sebesar jumlah potong.
- Menampilkan profil roll: Roll ID, Jenis•Motif•SKU Kain, Sisa Meter Terkini. Tanpa Sisa Berat Fisik dan tanpa lokasi gudang di kartu ini. (Berbeda dari mockup Stitch 3.2/3.3 yang masih menampilkan Sisa Berat Fisik — mockup tidak diperbarui, dokumen ini yang berlaku; lihat DESIGN §4.10.)
- Roll berstatus `Habis` tidak bisa dipotong lagi (tidak muncul di daftar roll aktif).
- **Tanpa proteksi stok:** transaksi tetap tercatat walau jumlah potong melebihi sisa sistem (mentolerir selisih presisi lapangan).
- **Status roll** ditentukan dari sisa meter vs meter saat kain datang:
  - **1 Roll** — sisa meter masih sama dengan meter saat kain datang (belum pernah dipotong).
  - **Sisa** — sudah ada potong dan sisa meter > 0.
  - **Habis** — sisa meter ≤ 0 menurut perhitungan aplikasi.
  - **Status "Habis" lebih valid daripada kolom status yang diisi staff** (mis. staff menulis "Sisa"/"Habis" pada cutting terakhir): status dihitung aplikasi, inputan staff tidak menimpa.
- **Kolom `Produk`, `SKU Produk`, dan `keyword_konversi_pcs` ditulis oleh aplikasi**, bukan lagi diturunkan rumus dari Kode Produksi (alur dibalik: produk dipilih dulu, kode lahir dari pilihan itu).
- Aplikasi **tidak menghitung** konversi meter↔pcs/estimasi — seluruh kalkulasi tersebut dikerjakan spreadsheet.

### 3.4. Pindah Gudang (Transfer) — bulk, lintas merek
- Alur: halaman awal (pilih Tulis / Scan) → scan kamera **atau** tulis Roll ID (cek VALID) → rekap + tambah roll lain dari gudang yang sama → pilih **gudang tujuan** → **satu klik Eksekusi** memindahkan semua roll dalam daftar. Setelah Eksekusi berhasil, aplikasi kembali ke 2.1 Pindah Gudang fresh (reset daftar roll, kunci asal dibuka, tanggal default hari ini, tujuan dikosongkan) dengan toast sukses agar staff langsung lanjut pindah berikutnya; bila gagal/tidak ada roll valid tetap di 2.4 + pesan jelas.
- Tanggal pindah default hari ini, bisa diubah dengan mengetuk tanggal di 2.1/2.4.
- **Pindah massal:** banyak roll, **satu asal gudang → satu tujuan gudang**. Gudang asal terkunci (tidak bisa campur asal).
- **Hanya gudang** — tidak ada pengaturan atau pemilihan ruangan.
- **Daftar gudang sama untuk kedua merek** (Master Gudang identik di kedua file) — itu sebabnya layar ini tidak memakai toggle merek.
- **Tanpa pemilihan merek.** Roll dari Malilkids maupun Anakkecilku dapat dipindah bersama; merek tiap roll ditentukan dari Roll ID-nya.
- Roll tak dikenal dilewati; roll yang sudah di gudang tujuan dilewati tanpa log baru. Tujuan tidak boleh sama dengan asal. Gudang tujuan yang belum ada otomatis terdaftar di Master Gudang.

### 3.5. Dashboard Kain (mencakup Laporan Summary)
- **4.1 Kain SKU (= Summary by SKU):** KPI (total SKU, roll aktif, total meter) + katalog SKU + filter multi-select jenis kain; berisi rekap kumulatif per SKU (**Roll Detail** dalam satuan roll, mis. 1.8), tanpa sinyal PO.
- **4.3 Kain Roll (= Summary by Roll ID):** daftar roll fisik + filter gudang & status; berisi rekap per roll (ukuran awal, total dipotong, sisa, status, lokasi gudang terkini).
- **4.5 Kain Admin** (Admin/Super Admin): checklist roll + unduh QR terpilih. Tombol Hapus di 4.5 = batalkan pilihan (kosongkan checklist), bukan hapus data. Unduhan = 1 file PDF A4 **landscape**: N roll = N/4 halaman (grid 2×2); per kotak: QR besar (isi Roll ID) + Roll ID tanpa label + Tanggal Datang (`25 Sep 2026`) + Jenis + Motif + Ukuran (Ukuran+Satuan dari History Datang) + No. Urut (parse dari Roll ID).
- Dashboard menampilkan **data operasional terkini**; spreadsheet (termasuk tab summary-nya) berperan untuk kalkulasi lanjutan dan audit, bukan sumber baca harian dashboard.
- **Merek dipilih lewat toggle di setiap layar Kain (4.1–4.5)**; isi layar hanya menampilkan data merek yang sedang dipilih.

### 3.6. Profil & Administrasi
- **Profil Staff:** info akun + tombol **Keluar Aplikasi** + tombol **Log Out**.
- **Profil Admin:** info akun + menu Akses & Sinkronisasi + menu Stock Opname + tombol **Keluar Aplikasi** + tombol **Log Out**.
- **Keluar Aplikasi** = menutup aplikasi saja; sesi login **tidak** dihapus (buka lagi → langsung masuk).
- **Log Out** = menghapus sesi login dan kembali ke layar 1.1; bila toggle "Ingat akun" sedang ON, toggle itu **ikut mati**. Data lokal (rolls/log) dipertahankan di HP, hanya sesi yang dihapus.
- **Akses & Sinkronisasi (Admin):** tombol Sinkron Penuh + Sinkron Database, daftar pengguna + tambah/edit/hapus. Hapus user hanya mencabut login; history inputnya tetap tersimpan.
- **Akses & Sinkronisasi (Super Admin):** sama, ditambah daftar admin + tambah admin baru. Ganti PIN Super Admin ada di 5.6 di atas Daftar Admin. Koneksi Spreadsheet + Uji Koneksi adalah halaman terpisah khusus Super Admin (bukan bagian 5.6).
- **Kartu pengumuman (5.1 & 5.2):** kartu coral berisi quotes di kedua layar profil menjadi slot pengumuman. Isinya berasal dari tab khusus `Pengumuman` di spreadsheet **Malilkids saja** (satu sumber, karena profil adalah halaman umum tanpa toggle merek — semua role/merek melihat isi yang sama). Isi tab: satu baris aktif — A2 = teks pengumuman, B2 = atribusi; admin menimpa baris itu tiap ada info baru. Footer kartu memakai atribusi dari sheet (default "- Pesan Harian Admin Gudang"). Diisi langsung via sheet oleh pemegang akses Editor (admin); tidak ada edit dari aplikasi. Bila belum pernah sinkron/offline, tampil teks default mockup ("Ketelitian memotong satu meter kain...").
- Seluruh inputan diteruskan ke spreadsheet inventory sesuai merek.

### 3.7. Stock Opname (Lockdown Mode)
- UI saat ini: tombol Stock Opname di 5.2 nonaktif dengan ikon gembok (pengembangan selanjutnya). Spek perilaku penuh di bawah tetap berlaku untuk saat fitur dibuka.
- Diaktifkan oleh Admin / Super Admin. Saat aktif, menu reguler (Beranda, Pindah Gudang, Cutting, Dashboard Kain) tertutup sementara; antarmuka fokus hanya pada scan QR + input stok opname fisik untuk audit.

## 4. Aturan Bisnis
- **Roll Aktif** = seluruh roll yang belum `Habis`, dihitung **dalam satuan roll**, bukan jumlah baris. Contoh: satu roll penuh + satu roll bersisa 0.8 → **Roll Aktif = 2**, sedangkan **Roll Detail = 1.8** (aturan ini sudah ada di Summary By SKU). Aplikasi hanya menampilkan roll yang aktif.
- **KPI "Roll Aktif"** (4.1/4.3) memakai definisi yang sama: hanya roll berstatus bukan `Habis`.
- **Kode Produksi unik:** kombinasi (merek, tanggal, SKU Produk, NN) tidak boleh sama — yang sama ditolak.
- **Tanpa blokir stok negatif** (§3.3).
- **Sisa roll hanya berkurang sebesar jumlah potong** — waste, reject, dan selisih presisi tidak ikut mengurangi (§3.3).
- **Satu Kode Produksi = banyak roll.** Simpan Transaksi menulis N baris (satu per roll) dengan Kode Produksi sama; tiap baris membawa roll_id/jenis/motif/SKU/meter sendiri.
- **Tanpa harga, tanpa sinyal PO** di seluruh aplikasi.
- **Tanpa ruangan** di pindah gudang (§3.4).
- **Data antar merek tidak bercampur**; setiap transaksi terikat pada satu merek. Pindah gudang tetap dapat menyentuh roll kedua merek karena layar itu memang lintas merek.
- **Roll ID unik global** (tanggal + jenis + motif + supplier + no. urut + ukuran) sehinggaroll selalu dapat dipastikan mereknya.
- **Mode offline** (lihat §4.1.1).

### 4.1 Aturan Detail & Offline
- **Roll Aktif** = seluruh roll yang belum `Habis`, dihitung **dalam satuan roll**, bukan jumlah baris. Contoh: satu roll penuh + satu roll bersisa 0.8 → **Roll Aktif = 2**, sedangkan **Roll Detail = 1.8** (aturan ini sudah ada di Summary By SKU). Aplikasi hanya menampilkan roll yang aktif.
- **KPI "Roll Aktif"** (4.1/4.3) memakai definisi yang sama: hanya roll berstatus bukan `Habis`.

**Mode Offline**
- **Cut dan Pindah tetap bisa dilakukan** saat offline; hasil input disimpan sebagai antrean lokal.
- **Cache di HP minimal**: ±1.000 roll (untuk cek VALID + sisa) dan log **3 hari**. Konsekuensi: scan roll yang tidak ada di cache saat offline akan ditolak — staff harus online dulu.
- **Login selalu online** (§3.1). Membuka app saat offline tanpa sesi sebelumnya → tertahan di 1.1.
- **Antrean dikirim tanpa koreksi staff** saat koneksi kembali.
- **Jika server menolak** (Kode Produksi bentrok dengan staff lain, atau sisa roll sudah berubah), transaksi **ditolak dan hilang** dari perangkat; staff diberi tahu saat sinkron lalu cukup input ulang dengan **NN baru**. Kain fisik tetap utuh dan bisa dipotong staff berikutnya — kecuali staff pertama memang jadi memotong.

## 5. Kebijakan Data (tingkat produk)
- Tiga jalur sinkronisasi, jangan dicampur:
  - **Selalu tersinkron** (otomatis, tanpa tombol, semua role): push setiap log transaksi secara realtime + pull baris hari-ini dari sheet (termasuk kolom sheet-side seperti Pcs Datang — ikut ketarik walau tidak dipakai aplikasi) + retry antrean umur berapa pun sampai terkirim.
  - **Sinkron Database** (tombol ringan, Admin/Super Admin, boleh kapan pun): pulling data acuan (master kain, master produk, roll datang) **+ 2 tab ringkasan** (Summary by Roll ID & by SKU).
  - **Sinkron Penuh** (tombol berat, Admin/Super Admin, jarang, di luar jam sibuk): tarik full History untuk rekonsiliasi; tidak menyentuh data harian.
- Saat Sinkron Penuh ditemukan selisih, **data Sheets dimenangkan** (acuan audit).
- **Mirror dulu, hitung mandiri sesudahnya.** Pada awalnya aplikasi mirror ke spreadsheet; selanjutnya aplikasi menghitung sendiri poin pentingnya (Jumlah Roll, Jumlah Roll Detail, Jumlah Meter, Lokasi Gudang — sesuai metrik UI). Setiap Sinkron Database/master dilakukan mirror ulang; bila ada perbedaan, **spreadsheet menang**.
- Penulisan input dirutekan per merek ke spreadsheet inventory masing-masing.
- **Append realtime.** Setiap transaksi cutting/pindah yang dieksekusi saat online langsung append baris ke sheet merek terkait — bukan menunggu tombol apa pun. Offline: antre di HP, terkirim otomatis begitu online kembali, umur antrean berapa pun.

## 6. Kriteria Keberhasilan
- Scan QR → input potong selesai **< 4 detik** per roll.
- Lokasi fisik roll **100%** cocok antara aplikasi dan gudang.
- **Dalam kondisi normal** (semua sinkron, tanpa edit manual di Sheets), angka pada aplikasi dan kedua spreadsheet **harus identik** — bukan "hampir sama". Setelah Sinkron Penuh, **Sheets menang pada selisih sekecil apa pun** (§5).
- **Tidak ada transaksi yang tercatat ke merek yang salah.**
- Setiap fitur di §2–§3.7 terpasang sesuai canvas desain (1.1–5.6), kecuali Stock Opname yang UI-nya masih terkunci.

## 6.1 Batasan yang Diketahui
- Transaksi offline yang ditolak server **hilang permanen** dari perangkat (§4.1). Akibatnya Summary By Code di spreadsheet dapat menunjukkan saldo berbeda dengan kenyataan gudang; karena Sheets menang, selisih itulah yang akan menimpa data aplikasi. Proses input ulang dengan NN baru adalah penyeimbangnya.
- Cache HP terbatas 1.000 roll / log 3 hari → sebagian roll tidak dapat di-scan saat offline.
- Tidak ada fitur notifikasi selisih di aplikasi; selisih hanya terlihat di spreadsheet.

## 7. Di Luar Cakupan (Non-Goals)
Harga/nilai aset, sinyal PO, blokir stok negatif, ruangan di pindah gudang, pendaftaran roll baru / ubah master dari HP, daftar master (kain, produk, roll) sebagai halaman tersendiri di aplikasi, perhitungan konversi meter↔pcs/estimasi di aplikasi (kecuali fallback Kg→meter §3.3), campur data antar merek.
